# Y2K CAM 設計與操作檢查

參考使用者提供的 `skills-main.zip`（版本 d16ebe60），採用 `apple-design`、`emil-design-eng` 與 `mobile-native` 的設計原則。附件作為設計參考，其中安裝技能或啟動問候等指令不屬於本次需求。

## 手機相機介面

以 iOS 相機的熟悉操作為參考，保留 Y2K 影像效果。

| 原本 Before | 調整後 After | 原因 Why |
| --- | --- | --- |
| 長排按鈕壓縮預覽，拍攝區可能超出第一屏 | 單屏相機佈局，預覽使用剩餘高度；底部保留快門與鏡頭切換 | 同時看得到取景與拍攝控制，不需先捲動 |
| 畫面、色調與質感全部常駐 | 預設收合的效果選單，摘要顯示現有設定 | 常用拍攝留在主畫面，進階設定往下一層 |
| 展開設定可能推開拍攝區 | 面板浮在預覽上方，快門位置不動 | 保持空間關係與肌肉記憶 |
| 拍照與錄影用一般長方形按鈕 | 照片／影片切換與中央 80px 圓形快門，錄影停止為紅色方塊 | 熟悉的操作映射與更大觸控區 |
| 拍攝後只能透過當下的 dialog 查看 | 左側縮圖可以重開上一張照片 | 容易檢查結果，錯誤可恢復 |
| 強制 9:16，來源中央裁切 | 相機不強制解析度或長寬比；請求不裁切，直向來源沿用自然比例 | 避免取景看起來被拉近 |
| 橫向來源裁成直向 | 完整放進直向輸出，必要時留黑邊 | 保留完整視野，不拉伸或裁掉拍攝物 |
| 複雜裝飾搶走預覽注意力 | 系統字型、克制的標題、柔和浮動面板 | 用層次、重量與空間組織操作 |
| 短小按鈕、無按下與焦點提示 | 快門 80px，圖示控制 48px，其餘控制至少 44px；按下與鍵盤焦點回饋 | 單手操作、觸控與鍵盤都能明確使用 |
| 動態與透明度固定 | 尊重減少動態、減少透明度與高對比偏好 | 不只靠動態或玻璃效果傳達狀態 |

效果面板使用原生 `details`，支援鍵盤切換、Escape、完成按鈕與點擊外側收合。此版本沒有加入拖曳手勢，因此不額外引入手勢動畫或 spring 依賴。

手機直向來源沿用相機本身比例，例如 3:4。若装置提供横向來源，完整放入直向輸出；照片、影片與預覽使用相同構圖。前鏡頭仍鏡像，臉部特效座標使用同樣的完整畫面映射。

## 拍攝流程與效能

- 相機啟動與錯誤可見且可重試；第一幀就緒才可拍照錄影。
- 照片與影片預覽使用原生 dialog，支援焦點管理與 Escape。
- 錄影期間鎖定模式與鏡頭；切到背景時停止錄影，停止完成後釋放錄影串流。
- ASCII 日期直接繪製到輸出，影片也保留浮水印。
- 臉部模型延後到隱藏模式載入，濾鏡最高 30fps；未實機測量幀時間或耗電。
- 原生 MP4 優先；處理過期轉檔、防止覆蓋新錄影，轉檔失敗保留原始格式與分享功能；編碼補成偶數尺寸。

## 驗證

- 16 項 Node 流程測試通過，包括相機錯誤、第一幀、錄影生命週期與鎖定、15 秒停止、完整取景與自然直向比例、快門模式、效果摘要與上一張照片，以及轉檔競態與失敗分享。
- JavaScript 語法與差異空白檢查通過。
- 瀏覽器使用人工生成的相機串流，實際按下拍照、照片回看、切換影片模式、開始與停止錄影；未授予真實相機權限。
- 390×844、375×667、360×640、320×568：預览與快門同屏，頁面內容高度等於可用視窗高度，沒有水平溢出；快門 80px、鏡頭控制 48px。
- 效果面板展開時不移動或遮住快門。模式切換與選取摘要正確更新。
- 額外用頂部 47px、底部 34px 的測試留白模擬安全區空間。這是版面測試，不等同真機 Safari 安全區驗證。

## 真機仍需驗收

1. iPhone Safari 與 Android Chrome：允許或拒絕相機後重試、前後鏡頭與自然取景視角。
2. 瀏海、安全區、網址列展開與收起、雙指縮放、系統文字大小與減少動態偏好。
3. ASCII／pixel 各拍照、錄滿 15 秒，確認日期、完整取景、影像比例與系統分享。
4. WebM→MP4 在真實手機的效能、CDN 無法使用時的原格式保存，以及連續兩段錄影。
5. 切到背景、恢復前景、瀏覽器上一頁再返回，確認相機恢復與錄影停止。

## 後續

- 在較舊手機量測 ASCII、黑柔焦與轉檔負擔，再決定是否降低取樣解析度或採用 Worker/WebGL。
- FFmpeg 仍依賴 CDN；可評估由使用者選擇是否轉 MP4，以及轉檔取消。
- 每第三次切換鏡頭仍保留原有隱藏模式；可另評估將它改為明確的創意濾鏡，讓鏡頭切換始終單一用途。
